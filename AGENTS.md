# Ailaan — project memory

Civic flood-alert app for KPK (Pakistan). Goal: accessible to non-literate
users (color + icon + audio), real flood warnings, honest about data quality.

## Stack & setup
- Next.js 16.3.0 (App Router, Turbopack), React, Tailwind v4, `geist`,
  `lucide-react`. No backend service — API lives in Route Handlers.
- **Package manager: npm** (decided with Jawad). `pnpm-lock.yaml` /
  `pnpm-workspace.yaml` are redundant and slated for removal (#2).
- Root `package.json` has `"type": "module"` so ESM sources load under
  `node --test`. Tests: `npm test` (`node --test`), 16 passing in `test/`.
- Commands: `npm run dev` / `build` / `start` / `lint` / `test`.

## Architecture
- `app/api/flood-status/route.js` — POST handler: validate district →
  rate-limit (per IP) → cached live fetch → labeled simulated fallback.
  Generic client errors only (no upstream internals).
- `lib/districts.js` — district centroids, bounding boxes, `isValidDistrict`
  (uses `Object.hasOwn`). 5 districts: nowshera, charsadda, peshawar, swat,
  mardan.
- `lib/floodStatus.js` — Google Flood Forecasting client, `severityToRisk`,
  `RISK_TO_SEVERITY`, `simulatedStatus`, `getFloodStatus`.
- `lib/rateLimit.js` — Upstash Redis REST limiter; in-memory per-instance
  fallback; fails open. `clientKeyFromHeaders` reads `x-forwarded-for`.
- `components/Hero.js` (~459 lines) — all client UI: district chips, language
  toggle, TTS `speak()`, `handleSubscribe`, `buildAlert()`.

## Data-honesty contract (critical)
Responses carry `source` (`"google-flood-forecasting"` | `"simulated"`) and
`simulated: true`. For a flood-warning product, never present simulated or
stale values as a live warning. This is the theme of #4, #9, #17.

## Deployment
Vercel. All env vars server-side — never `NEXT_PUBLIC_`. Uses
`GOOGLE_FLOOD_API_KEY`, `FLOOD_CACHE_SECONDS`, `UPSTREAM_TIMEOUT_MS`,
`UPSTASH_REDIS_REST_URL`/`TOKEN`, `RATE_LIMIT_MAX`, `GOOGLE_FLOOD_BASE_URL`
(see `.env.example`). See "Production caveats" below.

## Production caveats (#18)
- **Rate limiting:** `UPSTASH_REDIS_REST_URL`/`TOKEN` are **required in
  production** — the in-memory fallback is per-instance and ineffective on
  serverless. Verify with >`RATE_LIMIT_MAX` requests in a minute → expect `429`.
- **Vercel plan:** Hobby is **non-commercial** only. Move to Pro if Ailaan ever
  becomes commercial (payment/ads). Hobby caps function duration ~10 s.

## Workflow notes
- Private repo; PAT needs **Issues: write** + **Contents: write**. The GitHub
  **MCP tools use a separate stale credential that lacks write** — use
  `$GITHUB_TOKEN` via the API (curl/python) for PRs, issues, comments.
- Push with the token inline so `origin` stays clean:
  `git push https://${GITHUB_TOKEN}@github.com/juwwad/ailaan.git HEAD:refs/heads/<branch>`
- Issue states reachable only via API. `gh` is not logged in.
